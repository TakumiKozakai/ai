# todo-app 編集画面設計書

画面名: Todo編集画面。対応パス: `GET /todos/{id}/edit`（表示）／`POST /todos/{id}`（保存）。テンプレート: `templates/todo/edit.html`。対応コントローラ: `TodoController`（`app/src/main/java/com/example/todo/controller/TodoController.java`）。本書は `03_詳細設計/todo-app全体設計書.md` および実装（`app`）を根拠に作成した編集画面単体の詳細設計書であり、全体設計書・実装との間に矛盾は確認されなかった。一覧画面については「todo-app一覧画面設計書.md」を参照。

## 1. 画面項目定義

| 表示名（論理名） | 種別 | 必須性 | 初期値／表示内容 | 操作可否 | 備考 |
|---|---|---|---|---|---|
| 画面見出し | テキスト表示（`<h1>`） | - | 「Todo編集」 | 表示のみ | - |
| タイトル入力欄 | テキスト入力 | 必須（サーバー側） | 対象Todoの `title` | 入力可 | `Todo.title` にバインド |
| タイトルのエラーメッセージ | テキスト（条件表示） | - | 非表示（タイトルにバリデーションエラーがある場合のみ表示） | 表示のみ | サーバー側バリデーションエラー時に「タイトルは必須です」を表示 |
| 詳細入力欄 | テキスト入力 | 任意 | 対象Todoの `description`（未設定なら空） | 入力可 | `Todo.description` にバインド |
| 期限入力欄 | 日付入力（`type="date"`） | 任意 | 対象Todoの `dueDate`（未設定なら空） | 入力可 | `Todo.dueDate` にバインド |
| 状態セレクトボックス | セレクトボックス | - | 対象Todoの現在の状態（未着手／作業中／完了）が選択済み | 選択可 | 選択肢は未着手／作業中／完了の3値のみだが、画面表示は日本語ラベルであり、送信される `status` の値は `TodoStatus` の定数名（`NOT_STARTED`／`IN_PROGRESS`／`DONE`）である。一覧画面の状態セレクトと異なり、選択しても即時送信はされず、保存ボタン押下時にまとめて送信される |
| 保存ボタン | ボタン（submit） | - | 「保存」 | 押下可 | `POST /todos/{id}` を送信 |
| キャンセルリンク | リンク | - | 「キャンセルして一覧へ戻る」 | 遷移可 | `GET /todos` へ遷移。入力中の内容は保存されず破棄される |

## 2. 入力チェック内容

### 2.1 クライアント側

- 実装上、編集フォームに `required` などのHTML5必須属性やJavaScriptによる入力チェックは存在しない。タイトル・詳細ともにクライアント側の必須チェックは行われていない。
- 期限入力欄は `type="date"` であるため、対応ブラウザ標準の日付入力UIおよび型制約検証（constraint validation）が働く。`required` 属性は付与されていないため未入力は許容され、`min`/`max` 属性による範囲制約も設定されていない。

### 2.2 サーバー側

| 対象項目 | チェック内容 | エラーメッセージ | 発生条件 |
|---|---|---|---|
| タイトル | 必須（`@NotBlank`）。空文字・空白のみの入力は不可 | 「タイトルは必須です」 | `POST /todos/{id}` 送信時 |
| 期限 | `Todo.dueDate`（`LocalDate`）へは `@DateTimeFormat(pattern="yyyy-MM-dd")` により型変換される。Bean Validationによる追加の制約（過去日禁止等）は無いが、`yyyy-MM-dd` 形式に変換できない値が送信されると `BindingResult` にフィールドエラーとして記録され、保存されない | 画面上の表示なし（期限用のエラーメッセージ表示欄はテンプレートに存在しない） | `POST /todos/{id}` 送信時。通常の画面操作では `type="date"` のブラウザ標準検証により発生しない |
| 状態 | `POST /todos/{id}` のフォーム値を `@ModelAttribute` によって `TodoStatus`（`NOT_STARTED`／`IN_PROGRESS`／`DONE`）へバインドする際、型変換に失敗すると `BindingResult` にフィールドエラーとして記録される（例外は送出されない）。編集画面のセレクトボックスはこの3値のみを送信するため、通常の画面操作では変換に失敗しない | 画面上の表示なし（テンプレートに状態用のエラーメッセージ表示欄が無いため） | `NOT_STARTED`／`IN_PROGRESS`／`DONE` 以外の文字列を送信するリクエスト改ざん時のみ発生しうる |

- 詳細にはサーバー側のバリデーションは存在しない。

## 3. 画面処理

### 3.1 遷移元

- 通常は一覧画面の編集リンク（`GET /todos/{id}/edit`）から遷移する（詳細は「todo-app一覧画面設計書.md」の3.4を参照）。`GET /todos/{id}/edit` は独立したURLとして公開されており、遷移元を一覧画面に限定する実装（リファラチェック等）は無いため、URLを直接指定してアクセスすることも可能である。

### 3.2 初期表示

- `GET /todos/{id}/edit` にアクセスすると、`TodoController#editForm` が対象Todoを取得し、編集画面を表示する。
- モデルには対象Todo（`todo`）と状態の選択肢（`statuses` = `TodoStatus.values()`）が渡され、各入力欄には対象Todoの現在値が初期表示される。
- **対象ID不在時**: 対象Todoが存在しない場合は `IllegalArgumentException`（メッセージ「Todo not found: {id}」）が送出される。本アプリには当該例外を捕捉する共通例外処理が実装されていないため、Spring Bootのデフォルトエラーページ（Whitelabel Error Page、HTTPステータス500）が表示される。

### 3.3 保存（正常時／バリデーションエラー時／対象ID不在時）

- 保存ボタン押下により `POST /todos/{id}` が送信される。
- **正常時**: タイトルが入力されており、かつ期限・状態がそれぞれ `LocalDate`／`TodoStatus` へ型変換可能であるなど、`BindingResult` にエラーが記録されない場合、パスの `id` で対象Todoを再取得し、フォームの `title`・`description`・`dueDate`・`status` を反映して保存したうえで `/todos` へリダイレクトする。
- **バリデーションエラー時（タイトル未入力）**: タイトルが空白のみ／未入力の場合、`BindingResult` にエラーが記録され保存は行われず、フォーム内容（`id` を含む）と状態選択肢（`statuses`）を保持したまま `todo/edit` をそのまま再表示する（リダイレクトしない）。詳細・期限・状態の入力値は保持され、タイトル欄にエラーメッセージ「タイトルは必須です」が表示される。
- **期限が型変換できない値の場合（通常の画面操作では発生しない）**: 期限が `yyyy-MM-dd` 形式に型変換できない文字列で送信されると、`BindingResult` にフィールドエラーが記録され保存されず `todo/edit` が再表示される。編集画面のテンプレートには期限用のエラーメッセージ表示欄が無いため、タイトルが正しく入力されていれば、画面上にエラー表示のないまま入力内容を保持した編集画面が再表示される。
- **不正な状態値を送信した場合（通常の画面操作では発生しない）**: 状態が `NOT_STARTED`／`IN_PROGRESS`／`DONE` 以外の文字列で送信されると、2.2のとおり `BindingResult` にフィールドエラーが記録され `bindingResult.hasErrors()` が真になるため、保存は行われず `todo/edit` が再表示される。編集画面のテンプレートにはタイトル用のエラーメッセージ表示欄（`th:errors="*{title}"`）しか存在せず、状態用のエラーメッセージ表示欄が無いため、タイトルが正しく入力されていれば、画面上にエラー表示のないまま入力内容を保持した編集画面が再表示される。
- **対象ID不在時（バリデーション成功後）**: バリデーションを通過した後の保存処理内でも、対象Todoを `findById(id).orElseThrow(...)` で再取得しており、この時点で対象が存在しない場合（例: 編集画面表示後、保存前に他操作で当該Todoが削除された場合など）は初期表示時と同様に `IllegalArgumentException` が送出され、Whitelabel Error Page（HTTPステータス500）が表示される。

### 3.4 キャンセル

- キャンセルリンク押下により `GET /todos` へ遷移する。フォームの入力内容は送信されず、対象Todoの状態は変更されない。

### 3.5 例外発生時の共通事項

- 本画面の各処理（Todoの取得・保存）でDBアクセス例外等が発生した場合の専用の例外処理・復旧処理は実装されていない。その場合、各処理は通常の成功時の遷移（リダイレクト）には進まない。
