# ecsite ログイン画面設計書

画面名: ログイン画面（SC-07）。対応パス: `GET /login`（表示）／`POST /login`（認証。Spring Security が処理）。テンプレート: `templates/auth/login.html`。対応コントローラ: `LoginController`（表示のみ。`app/src/main/java/com/example/ecsite/controller/LoginController.java`）。認証処理は Spring Security のフォームログイン（設定: `app/src/main/java/com/example/ecsite/config/SecurityConfig.java`、ユーザー取得: `app/src/main/java/com/example/ecsite/service/LoginUserDetailsService.java`）で行う。本書は `doc/詳細設計/ecsite-ER図・テーブル定義書.md` および `doc/詳細設計/ecsite-画面一覧・共通仕様書.md` を根拠に作成したログイン画面単体の詳細設計書であり、実装前の新規設計である。会員登録画面については「ecsite-会員登録画面設計書.md」を参照。

## 1. 画面項目定義

共通ヘッダーは「ecsite-画面一覧・共通仕様書.md」の3章を参照。

| 表示名（論理名） | 種別 | 必須性 | 初期値／表示内容 | 操作可否 | 備考 |
|---|---|---|---|---|---|
| 画面見出し | テキスト表示（`<h1>`） | - | 「ログイン」 | 表示のみ | - |
| ログイン失敗メッセージ | テキスト（条件表示） | - | 「メールアドレスまたはパスワードが正しくありません」 | 表示のみ | `GET /login?error` の場合のみ赤字で表示 |
| ログアウト完了メッセージ | テキスト（条件表示） | - | 「ログアウトしました」 | 表示のみ | `GET /login?logout` の場合のみ緑字で表示 |
| メールアドレス入力欄 | メール入力（`type="email"`） | 必須 | 空 | 入力可 | `required`・`maxlength="255"`。送信パラメータ名は `email` |
| パスワード入力欄 | パスワード入力（`type="password"`） | 必須 | 空 | 入力可 | `required`・`maxlength="64"`。入力値は伏字表示。送信パラメータ名は `password` |
| ログインボタン | ボタン（submit） | - | 「ログイン」 | 押下可 | `POST /login` を送信 |
| 会員登録リンク | リンク | - | 「会員登録はこちら」 | 遷移可 | `GET /signup` へ遷移 |

## 2. 入力チェック内容

### 2.1 クライアント側

- メールアドレス・パスワードに `required` を付与する。未入力の場合はブラウザ標準の制約検証により送信されない。
- メールアドレス入力欄は `type="email"` のため、メールアドレスの形式でない値は送信されない。
- 各入力欄に `maxlength`（1章の備考のとおり）を付与する。
- JavaScriptによる入力チェックは行わない。

### 2.2 サーバー側

- 入力値の形式チェック（Bean Validation）は行わない。未入力・形式不正の値が送信された場合も、認証失敗として扱う。
- 認証は以下のとおり行い、失敗時の理由（メールアドレスが未登録か、パスワードが誤りか）は区別せず同じメッセージを表示する。

| 対象項目 | チェック内容 | エラーメッセージ | 発生条件 |
|---|---|---|---|
| メールアドレス | 前後の空白を除去し小文字に変換した値が `users.email` に存在すること | 「メールアドレスまたはパスワードが正しくありません」 | 未登録のメールアドレスを入力した場合 |
| パスワード | `users.password_hash` と BCrypt で照合して一致すること | 「メールアドレスまたはパスワードが正しくありません」 | パスワードが誤っている場合 |

- ログイン失敗回数によるアカウントロックは行わない。

## 3. 画面処理

### 3.1 遷移元

- 共通ヘッダーのログインリンク、商品詳細画面のログイン誘導リンク、会員登録画面のログイン画面へのリンクから遷移する。
- ログインが必要な画面に未ログインでアクセスした場合、Spring Security によりログイン画面へリダイレクトされる（「ecsite-画面一覧・共通仕様書.md」の4章）。
- **ログイン中にアクセスした場合**: `GET /login` は画面を表示せず `/products` へリダイレクトする。

### 3.2 初期表示

- `GET /login` にアクセスすると、`LoginController#form` がログイン画面を表示する。リクエストパラメータ `error` があればログイン失敗メッセージ、`logout` があればログアウト完了メッセージを表示する。

### 3.3 ログイン（成功時／失敗時）

- メールアドレス・パスワードを入力してログインボタンを押下すると、`POST /login`（`email`・`password`）が送信され、Spring Security が認証する。
- **成功時**: セッションIDを再発行したうえで（セッション固定攻撃対策。Spring Security の既定動作）認証情報をセッションに保存する。ログイン前にログインが必要な画面（GET）へアクセスしてリダイレクトされていた場合はその画面へ、それ以外は `/products` へリダイレクトする。
- **失敗時**: `/login?error` へリダイレクトし、ログイン失敗メッセージを表示する。メールアドレス・パスワードの入力値は保持しない（空で表示する）。

### 3.4 会員登録画面への遷移

- 会員登録リンク押下により `GET /signup` へ遷移する。

### 3.5 例外発生時の共通事項

- 認証処理中にDBアクセス例外等が発生した場合は、ログイン失敗と同様に `/login?error` へリダイレクトする（Spring Security が `InternalAuthenticationServiceException` を認証失敗として扱うため）。例外の詳細はログにのみ出力する。
- 画面表示中の例外は、「ecsite-画面一覧・共通仕様書.md」の6章のとおり500エラーページを表示する。
