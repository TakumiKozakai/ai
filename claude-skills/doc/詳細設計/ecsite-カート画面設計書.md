# ecsite カート画面設計書

画面名: カート画面（SC-03）。URL: `/cart`。画面コンポーネント: `app/frontend/src/pages/CartPage.tsx`。使用API: A-08 `GET /api/cart`、A-10 `PATCH /api/cart/items/:cartItemId`、A-11 `DELETE /api/cart/items/:cartItemId`（`app/backend/internal/handler/cart_handler.go`）。本書は `doc/詳細設計/ecsite-ER図・テーブル定義書.md`、`doc/詳細設計/ecsite-画面一覧・共通仕様書.md`、`doc/詳細設計/ecsite-API設計書.md` を根拠に作成したカート画面単体の詳細設計書であり、実装前の新規設計である。カートへの商品追加は「ecsite-商品詳細画面設計書.md」、購入手続きは「ecsite-購入手続き画面設計書.md」を参照。

## 1. 画面項目定義

共通ヘッダー・画面メッセージは「ecsite-画面一覧・共通仕様書.md」の3章・5章を参照。

### 1.1 カート明細

カートに商品が1件以上ある場合のみ表示する。明細は `cart_items.created_at` の昇順（カートに入れた順）で並べ、1行ごとに以下の項目を持つ。

| 表示名（論理名） | 種別 | 必須性 | 初期値／表示内容 | 操作可否 | 備考 |
|---|---|---|---|---|---|
| 商品画像 | 画像 | - | `products.image_url`（未設定なら代替画像） | 表示のみ | 代替テキストは商品名 |
| 商品名リンク | リンク | - | `products.name` | 遷移可 | `/products/{productId}` へ遷移。商品が非公開の場合はリンクにせずテキスト表示 |
| 単価表示 | テキスト表示 | - | 現在の `products.price`（例:「¥1,980」） | 表示のみ | カートには単価を保持しないため、常に最新の価格を表示する |
| 数量入力欄 | 数値入力（`type="number"`） | 必須 | `cart_items.quantity` | 入力可 | `min="1"`・`max="10"`・`required` |
| 更新ボタン | ボタン（submit） | - | 「更新」 | 押下可 | 行ごとに配置。A-10 `PATCH /api/cart/items/{cartItemId}`（`quantity`）を呼び出す。応答待ちの間は押下不可 |
| 小計表示 | テキスト表示 | - | 単価 × 数量（例:「¥3,960」） | 表示のみ | - |
| 削除ボタン | ボタン | - | 「削除」 | 押下可 | 行ごとに配置。A-11 `DELETE /api/cart/items/{cartItemId}` を呼び出す。確認ダイアログは表示しない。応答待ちの間は押下不可 |
| 購入不可メッセージ | テキスト（条件表示） | - | 下記のいずれか | 表示のみ | 購入できない状態の行のみ、赤字で表示 |

購入不可メッセージの表示条件（A-08 の `problem`）:

| 条件 | `problem` | 表示内容 |
|---|---|---|
| 商品が非公開（`is_published = false`） | `UNPUBLISHED` | 「この商品は現在購入できません。削除してください」 |
| 在庫数が0 | `OUT_OF_STOCK` | 「在庫切れです。削除してください」 |
| 在庫数が1以上かつ数量より少ない | `INSUFFICIENT_STOCK` | 「在庫が不足しています（在庫: {在庫数}点）。数量を変更してください」 |

### 1.2 合計・操作

| 表示名（論理名） | 種別 | 必須性 | 初期値／表示内容 | 操作可否 | 備考 |
|---|---|---|---|---|---|
| 合計点数表示 | テキスト表示 | - | 「合計 {数量の合計}点」 | 表示のみ | カートに商品が1件以上ある場合のみ表示 |
| 商品合計表示 | テキスト表示 | - | 「商品合計 ¥{小計の合計}」 | 表示のみ | カートに商品が1件以上ある場合のみ表示。送料は含まない（購入手続き画面で表示） |
| 購入不可の案内 | テキスト（条件表示） | - | 「購入できない商品がカートに含まれています。数量を変更するか削除してください」 | 表示のみ | 購入不可メッセージが表示されている行が1件以上ある場合のみ表示 |
| 購入手続きへ進むボタン | ボタン | - | 「購入手続きへ進む」 | 押下可／押下不可 | カートに商品が1件以上ある場合のみ表示。`/checkout` へ遷移。購入不可の行が1件以上ある場合（A-08 の `purchasable` が `false`）は `disabled`（押下不可） |
| 買い物を続けるリンク | リンク | - | 「買い物を続ける」 | 遷移可 | `/products` へ遷移 |

### 1.3 その他

| 表示名（論理名） | 種別 | 必須性 | 初期値／表示内容 | 操作可否 | 備考 |
|---|---|---|---|---|---|
| 画面見出し | テキスト表示（`<h1>`） | - | 「カート」 | 表示のみ | - |
| 0件時メッセージ | テキスト表示（条件表示） | - | 「カートに商品が入っていません」 | 表示のみ | カートが0件の場合のみ表示 |

## 2. 入力チェック内容

### 2.1 クライアント側

- 数量入力欄に `type="number"`・`min="1"`・`max="10"`・`required` を付与し、1行ごとに `<form>` で囲む。空・1未満・11以上・小数の値ではブラウザ標準の制約検証により更新ボタンを押してもAPIを呼び出さない。
- JavaScriptによる独自の入力チェックは行わない。

### 2.2 サーバー側

A-10 `PATCH /api/cart/items/{cartItemId}` 呼び出し時に以下の順でチェックする。

| 対象項目 | チェック内容 | エラーメッセージ | 発生条件 |
|---|---|---|---|
| カート明細（`cartItemId`） | ログインユーザーの `cart_items` として存在すること | 表示なし（`404 NOT_FOUND`。画面はカートを再取得して表示し直す） | 存在しない・他ユーザーのIDを送信するリクエスト改ざん時、または別タブで削除済みの明細を更新した場合 |
| 数量 | 1〜10の整数であること | 「数量は1〜10の整数で入力してください」（`400 VALIDATION_ERROR`、`fieldErrors.quantity`） | 通常の画面操作ではブラウザの制約検証により発生しない。リクエスト改ざん時のみ発生しうる |
| 商品の公開状態 | 商品が公開中であること | 「この商品は現在購入できません」（`400 PRODUCT_UNPUBLISHED`） | 非公開になった商品の数量を変更した場合 |
| 数量（在庫） | 在庫数（`stock_quantity`）以下であること | 「在庫が不足しています（在庫: {在庫数}点）」（`400 INSUFFICIENT_STOCK`） | 在庫数を超える数量に変更した場合 |

- エラーメッセージは、カート画面の画面メッセージ（エラー）として表示する。

## 3. 画面処理

### 3.1 遷移元

- 商品詳細画面のカートに入れるボタン（追加成功後の遷移）、共通ヘッダーのカートリンク、購入手続き画面のカートに戻るリンク・注文確定できなかった場合の遷移から表示される。
- ログインが必要。未ログインの場合はログイン画面へ遷移し、ログイン後にカート画面へ戻る（「ecsite-画面一覧・共通仕様書.md」の4.4）。
- 他の画面から画面メッセージ（例: 商品詳細画面の「カートに商品を追加しました」、購入手続き画面の「カートに商品が入っていません」）を渡された場合は、その画面メッセージを表示する。

### 3.2 初期表示

- `/cart` を表示すると、A-08 `GET /api/cart` でログインユーザーのカートを取得し、カート画面を表示する。
- 非公開・在庫不足の商品も明細として表示し、1.1 の購入不可メッセージを付ける（カートから自動では削除しない）。
- 単価・小計・合計は、取得時点の `products.price` で計算された値（A-08 の値）を表示する。

### 3.3 数量変更（正常時／エラー時）

- 数量入力欄を変更して更新ボタンを押下すると、A-10 `PATCH /api/cart/items/{cartItemId}`（`{ "quantity": {数量} }`）を呼び出す。
- **正常時**（`200`）: バックエンドは対象明細の `quantity` と `updated_at` を更新し、変更後のカート全体を返す。画面は返されたカートで表示し直し、画面メッセージ（成功）「数量を変更しました」を表示する。共通ヘッダーのカート数量を更新する。
- **エラー時**（`400`）: 数量は変更されない。画面メッセージ（エラー）でAPIの `message`（`VALIDATION_ERROR` の場合は `fieldErrors.quantity`）を表示し、A-08 でカートを再取得して表示し直す（数量入力欄は変更前の数量に戻る）。
- **対象明細が存在しない場合**（`404`）: A-08 でカートを再取得して表示し直す（画面メッセージは表示しない）。

### 3.4 削除

- 削除ボタンを押下すると、A-11 `DELETE /api/cart/items/{cartItemId}` を呼び出す。確認ダイアログは表示せず、押下と同時に削除される。
- **正常時**（`200`）: バックエンドはログインユーザーの対象明細を削除し、削除後のカート全体を返す。画面は返されたカートで表示し直し、画面メッセージ（成功）「カートから商品を削除しました」を表示する。共通ヘッダーのカート数量を更新する。最後の1件を削除した場合は0件時メッセージが表示される。
- **対象明細が存在しない場合**（`404`。他ユーザーのID、削除済み等）: A-08 でカートを再取得して表示し直す（画面メッセージは表示しない）。

### 3.5 購入手続き画面への遷移

- 購入手続きへ進むボタン押下により `/checkout` へ遷移する（画面としては「ecsite-購入手続き画面設計書.md」を参照）。購入不可の行がある場合はボタンが押下できない。

### 3.6 例外発生時の共通事項

- A-08・A-10・A-11 が `401` を返した場合は、ログイン画面へ遷移する（「ecsite-画面一覧・共通仕様書.md」の4.4）。
- `500` を返した場合、またはバックエンドに接続できない場合は、「ecsite-画面一覧・共通仕様書.md」の6章のとおりシステムエラー画面を表示する。数量変更・削除はロールバックされ、カートは変更されない。
