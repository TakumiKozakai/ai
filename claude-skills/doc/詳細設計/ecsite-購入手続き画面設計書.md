# ecsite 購入手続き画面設計書

画面名: 購入手続き画面（SC-04）。URL: `/checkout`。画面コンポーネント: `app/frontend/src/pages/CheckoutPage.tsx`。使用API: A-12 `GET /api/checkout`（`app/backend/internal/handler/checkout_handler.go`）、A-13 `POST /api/orders`（`app/backend/internal/handler/order_handler.go`）。注文確定処理はバックエンドの `app/backend/internal/service/order_service.go` で行う。本書は `doc/詳細設計/ecsite-ER図・テーブル定義書.md`、`doc/詳細設計/ecsite-画面一覧・共通仕様書.md`、`doc/詳細設計/ecsite-API設計書.md` を根拠に作成した購入手続き画面単体の詳細設計書であり、実装前の新規設計である。カート画面については「ecsite-カート画面設計書.md」、注文完了画面については「ecsite-注文完了画面設計書.md」を参照。

## 1. 画面項目定義

共通ヘッダー・画面メッセージは「ecsite-画面一覧・共通仕様書.md」の3章・5章を参照。

### 1.1 注文内容

カート内の商品を `cart_items.created_at` の昇順で1行ずつ表示する（変更はできない）。

| 表示名（論理名） | 種別 | 必須性 | 初期値／表示内容 | 操作可否 | 備考 |
|---|---|---|---|---|---|
| 商品名表示 | テキスト表示 | - | `products.name` | 表示のみ | リンクにしない |
| 単価表示 | テキスト表示 | - | 現在の `products.price`（例:「¥1,980」） | 表示のみ | - |
| 数量表示 | テキスト表示 | - | `cart_items.quantity`（例:「2点」） | 表示のみ | - |
| 小計表示 | テキスト表示 | - | 単価 × 数量 | 表示のみ | - |

### 1.2 金額

| 表示名（論理名） | 種別 | 必須性 | 初期値／表示内容 | 操作可否 | 備考 |
|---|---|---|---|---|---|
| 商品合計表示 | テキスト表示 | - | 小計の合計（例:「¥3,960」） | 表示のみ | - |
| 送料表示 | テキスト表示 | - | 商品合計が5,000円以上なら「¥0」、5,000円未満なら「¥500」 | 表示のみ | 送料はバックエンドで計算する（A-12 の `shippingFee`） |
| 送料の案内 | テキスト表示 | - | 「5,000円以上のご購入で送料無料」 | 表示のみ | 常に表示 |
| 支払総額表示 | テキスト表示 | - | 商品合計 + 送料 | 表示のみ | - |

### 1.3 配送先

| 表示名（論理名） | 種別 | 必須性 | 初期値／表示内容 | 操作可否 | 備考 |
|---|---|---|---|---|---|
| 登録済み住所ラジオボタン | ラジオボタン | 必須（いずれか1つ） | 下記「初期選択」のとおり | 選択可 | ログインユーザーの `addresses` 1件につき1つ表示。並び順は既定の住所（`is_default = true`）を先頭、以降は `created_at` 昇順。ラベルは「{宛名} 〒{郵便番号} {都道府県}{市区町村}{町名・番地} {建物名} TEL {電話番号}」。値は `addresses.id` |
| 新しい住所ラジオボタン | ラジオボタン | 必須（いずれか1つ） | 下記「初期選択」のとおり | 選択可 | 「新しい住所を入力する」。値は `new` |
| 宛名入力欄 | テキスト入力 | 条件付き必須（サーバー側） | 空 | 入力可 | `maxlength="100"` |
| 郵便番号入力欄 | テキスト入力 | 条件付き必須（サーバー側） | 空（プレースホルダ「1234567」） | 入力可 | `maxlength="7"`・`inputmode="numeric"`。ハイフンなしで入力する |
| 都道府県セレクトボックス | セレクトボックス | 条件付き必須（サーバー側） | 「選択してください」（値は空） | 選択可 | 選択肢は「選択してください」と47都道府県（A-12 の `prefectures`。北海道〜沖縄県、JIS X 0401 の順） |
| 市区町村入力欄 | テキスト入力 | 条件付き必須（サーバー側） | 空 | 入力可 | `maxlength="100"` |
| 町名・番地入力欄 | テキスト入力 | 条件付き必須（サーバー側） | 空 | 入力可 | `maxlength="200"` |
| 建物名入力欄 | テキスト入力 | 任意 | 空 | 入力可 | `maxlength="200"` |
| 電話番号入力欄 | テキスト入力 | 条件付き必須（サーバー側） | 空（プレースホルダ「09012345678」） | 入力可 | `maxlength="11"`・`inputmode="numeric"`。ハイフンなしで入力する |
| 配送先のエラーメッセージ | テキスト（条件表示） | - | 非表示（エラーがある場合のみ各項目の下に表示） | 表示のみ | 2.2 のエラーメッセージを項目ごとに表示（A-13 の `fieldErrors`） |

- 新しい住所の入力欄は、選択中のラジオボタンにかかわらず常に表示する。入力値は新しい住所ラジオボタンを選択している場合のみ使用し、登録済み住所を選択している場合は入力されていても無視する（エラーにもしない）。

## 2. 入力チェック内容

### 2.1 クライアント側

- 新しい住所の各入力欄に `maxlength`（1.3 の備考のとおり）を付与する。上限を超える文字数は入力できない。
- 新しい住所の入力欄は「新しい住所を入力する」選択時のみ必須となるため、`required` 属性は付与しない。支払方法のラジオボタンにも `required` を付与しない。必須チェックはすべてサーバー側で行う。
- JavaScriptによる独自の入力チェックは行わない。

### 2.2 サーバー側

A-13 `POST /api/orders` 呼び出し時にチェックする。文字列項目は前後の空白（半角・全角スペース）を除去してからチェックする。エラー時は `400 VALIDATION_ERROR` を返し、`fieldErrors` のキーは下表の括弧内とする。

| 対象項目 | チェック内容 | エラーメッセージ | 発生条件 |
|---|---|---|---|
| 配送先の選択（`addressId`） | `new` またはログインユーザーの `addresses.id` であること | 「配送先を選択してください」 | 未選択・他ユーザーや存在しない住所IDを送信するリクエスト改ざん時 |
| 宛名（`recipientName`） | 必須 | 「宛名を入力してください」 | 新しい住所を選択し、未入力の場合 |
| 宛名（`recipientName`） | 100文字以内 | 「宛名は100文字以内で入力してください」 | 新しい住所を選択した場合。画面操作では `maxlength` により発生しない |
| 郵便番号（`postalCode`） | 必須 | 「郵便番号を入力してください」 | 新しい住所を選択し、未入力の場合 |
| 郵便番号（`postalCode`） | 半角数字7桁（`^[0-9]{7}$`） | 「郵便番号はハイフンなしの半角数字7桁で入力してください」 | 新しい住所を選択し、7桁未満・数字以外（ハイフン・全角数字を含む）の場合 |
| 都道府県（`prefecture`） | 47都道府県のいずれかであること | 「都道府県を選択してください」 | 新しい住所を選択し、未選択の場合。一覧に無い値を送信するリクエスト改ざん時 |
| 市区町村（`city`） | 必須 | 「市区町村を入力してください」 | 新しい住所を選択し、未入力の場合 |
| 市区町村（`city`） | 100文字以内 | 「市区町村は100文字以内で入力してください」 | 新しい住所を選択した場合。画面操作では `maxlength` により発生しない |
| 町名・番地（`addressLine`） | 必須 | 「町名・番地を入力してください」 | 新しい住所を選択し、未入力の場合 |
| 町名・番地（`addressLine`） | 200文字以内 | 「町名・番地は200文字以内で入力してください」 | 新しい住所を選択した場合。画面操作では `maxlength` により発生しない |
| 建物名（`building`） | 200文字以内 | 「建物名は200文字以内で入力してください」 | 新しい住所を選択した場合。画面操作では `maxlength` により発生しない |
| 電話番号（`phoneNumber`） | 必須 | 「電話番号を入力してください」 | 新しい住所を選択し、未入力の場合 |
| 電話番号（`phoneNumber`） | 半角数字10〜11桁（`^[0-9]{10,11}$`） | 「電話番号はハイフンなしの半角数字10〜11桁で入力してください」 | 新しい住所を選択し、10桁未満・数字以外（ハイフン・全角数字を含む）の場合 |
| 支払方法（`paymentMethod`） | `CREDIT_CARD`／`BANK_TRANSFER`／`CASH_ON_DELIVERY` のいずれかであること | 「支払方法を選択してください」 | 未選択の場合。一覧に無い値を送信するリクエスト改ざん時 |

- 同じ項目で必須と形式・文字数の両方に該当する場合は、必須のエラーメッセージのみ返す。
- 複数の項目にエラーがある場合は、すべての項目のエラーメッセージを同時に返し、画面にも同時に表示する。

## 3. 画面処理

### 3.1 遷移元

- 通常はカート画面の購入手続きへ進むボタンから遷移する。`/checkout` はURLを直接指定しても表示できるため、表示前に 3.2 の事前チェックを行う。
- ログインが必要。未ログインの場合はログイン画面へ遷移し、ログイン後に購入手続き画面へ戻る（「ecsite-画面一覧・共通仕様書.md」の4.4）。

### 3.2 初期表示

- `/checkout` を表示すると、A-12 `GET /api/checkout` でログインユーザーのカート・金額・住所・都道府県一覧を取得し、購入手続き画面を表示する。
- **事前チェック**: A-12 が `409` を返した場合は画面を表示せず、`/cart` へ遷移してAPIの `message` を画面メッセージ（エラー）として表示する。
  - カートが0件（`CART_EMPTY`）: 「カートに商品が入っていません」
  - カートに購入不可の商品（非公開・在庫切れ・在庫不足。「ecsite-カート画面設計書.md」の1.1 の条件）がある（`CART_NOT_PURCHASABLE`）: 「購入できない商品がカートに含まれています。数量を変更するか削除してください」

### 3.3 注文確定（正常時／バリデーションエラー時／確定できない場合）

- 配送先・支払方法を選択して注文を確定するボタンを押下すると、A-13 `POST /api/orders` を呼び出す（リクエストは「ecsite-API設計書.md」の A-13）。
- **バリデーションエラー時**（`400`）: 注文は作成されない。購入手続き画面にとどまり、配送先の選択、新しい住所の入力値、支払方法の選択はそのまま保持して、エラーのある項目の下に `fieldErrors` のメッセージを表示する。前回表示していたエラーメッセージは消してから表示する。
- **正常時**（`201`）: バックエンドの注文確定処理（`order_service.go`）が以下を1トランザクションで行う（「ecsite-ER図・テーブル定義書.md」の5章）。
  0. カート・商品を取得し、3.2 と同じ事前チェックを行う。該当する場合はトランザクションをロールバックし、`409`（`CART_EMPTY`／`CART_NOT_PURCHASABLE`）を返す（画面表示後に別タブでカートを変更した場合、在庫が減った場合など）
  1. 新しい住所を選択した場合は `addresses` に保存する。ログインユーザーに既定の住所が無ければ `is_default = true`、あれば `false` とする
  2. カート内の各商品の `products.stock_quantity` から数量を減算する（`version` による楽観ロック。`UPDATE ... WHERE id = ? AND version = ?` の更新件数が0件なら競合）
  3. `orders` を作成する。金額（商品合計・送料・支払総額）は**確定時点**の `products.price` で計算し、配送先は選択した住所の値をコピーする。`status` は `ORDERED`、`ordered_at` は現在日時とする
  4. カートの各明細について `order_items` を作成する（商品名・単価を `products` からコピー）
  5. ログインユーザーの `cart_items` を全件削除する

  画面は共通ヘッダーのカート数量を更新し、`/orders/{注文番号}/complete` へ遷移する（履歴を置き換える。画面としては「ecsite-注文完了画面設計書.md」を参照）。
- **注文番号**: `yyyyMMdd-` + 6桁の乱数（例: `20260921-483920`）とする。`yyyyMMdd` は注文日（日本時間）。既存の注文番号と重複した場合は乱数を取り直し、3回重複した場合はシステムエラー（`500`）とする。
- **カートの状態により確定できない場合**（`409 CART_EMPTY`／`CART_NOT_PURCHASABLE`）: `/cart` へ遷移し、APIの `message` を画面メッセージ（エラー）として表示する。
- **他の購入と競合した場合**（`409 ORDER_CONFLICT`）: 楽観ロックの競合によりトランザクション全体がロールバックされる（新しい住所も保存されない）。`/cart` へ遷移し、画面メッセージ（エラー）「他のお客様の購入と重なったため注文を確定できませんでした。カートの内容を確認して、もう一度お試しください」を表示する。
- 画面表示後に商品の価格が変更されていた場合、注文は確定時点の価格で作成される（画面に表示していた金額と異なっても警告は表示しない）。
- 二重送信: 応答待ちの間はボタンを押下不可にする。それでも2回目の A-13 が届いた場合は、1回目でカートが空になっているため `409 CART_EMPTY` となり、注文は1件だけ作成される。

### 3.4 カート画面への遷移

- カートに戻るリンク押下により `/cart` へ遷移する。入力内容は送信されず、注文・住所は作成されない。

### 3.5 例外発生時の共通事項

- A-12・A-13 が `401` を返した場合は、ログイン画面へ遷移する（「ecsite-画面一覧・共通仕様書.md」の4.4）。
- `500` を返した場合、またはバックエンドに接続できない場合は、「ecsite-画面一覧・共通仕様書.md」の6章のとおりシステムエラー画面を表示する。注文確定処理はロールバックされ、在庫・注文・住所・カートは処理前の状態のままとなる。
