# ecsite 購入手続き画面設計書

画面名: 購入手続き画面（SC-04）。対応パス: `GET /checkout`（表示）／`POST /checkout`（注文確定）。テンプレート: `templates/checkout/index.html`。対応コントローラ: `CheckoutController`（`app/src/main/java/com/example/ecsite/controller/CheckoutController.java`）。注文確定処理は `OrderService`（`app/src/main/java/com/example/ecsite/service/OrderService.java`）で行う。本書は `doc/詳細設計/ecsite-ER図・テーブル定義書.md` および `doc/詳細設計/ecsite-画面一覧・共通仕様書.md` を根拠に作成した購入手続き画面単体の詳細設計書であり、実装前の新規設計である。カート画面については「ecsite-カート画面設計書.md」、注文完了画面については「ecsite-注文完了画面設計書.md」を参照。

## 1. 画面項目定義

共通ヘッダー・フラッシュメッセージは「ecsite-画面一覧・共通仕様書.md」の3章・5章を参照。

### 1.1 注文内容

カート内の商品を `cart_items.created_at` の昇順で1行ずつ表示する（変更はできない）。

| 表示名（論理名） | 種別 | 必須性 | 初期値／表示内容 | 操作可否 | 備考 |
|---|---|---|---|---|---|
| 商品名表示 | テキスト表示 | - | `products.name` | 表示のみ | リンクにしない |
| 単価表示 | テキスト表示 | - | 現在の `products.price`（例:「¥1,980」） | 表示のみ | - |
| 数量表示 | テキスト表示 | - | `cart_items.quantity`（例:「2点」） | 表示のみ | - |
| 小計表示 | テキスト表示 | - | 単価 × 数量 | 表示のみ | - |

### 1.2 金額

| 表示名（論理名） | 種別 | 必須性 | 初期値／表示内容 | 操作可否 | 備考 |
|---|---|---|---|---|---|
| 商品合計表示 | テキスト表示 | - | 小計の合計（例:「¥3,960」） | 表示のみ | - |
| 送料表示 | テキスト表示 | - | 商品合計が5,000円以上なら「¥0」、5,000円未満なら「¥500」 | 表示のみ | - |
| 送料の案内 | テキスト表示 | - | 「5,000円以上のご購入で送料無料」 | 表示のみ | 常に表示 |
| 支払総額表示 | テキスト表示 | - | 商品合計 + 送料 | 表示のみ | - |

### 1.3 配送先

| 表示名（論理名） | 種別 | 必須性 | 初期値／表示内容 | 操作可否 | 備考 |
|---|---|---|---|---|---|
| 登録済み住所ラジオボタン | ラジオボタン | 必須（いずれか1つ） | 下記「初期選択」のとおり | 選択可 | ログインユーザーの `addresses` 1件につき1つ表示。並び順は既定の住所（`is_default = true`）を先頭、以降は `created_at` 昇順。ラベルは「{宛名} 〒{郵便番号} {都道府県}{市区町村}{町名・番地} {建物名} TEL {電話番号}」。送信値は `addresses.id` |
| 新しい住所ラジオボタン | ラジオボタン | 必須（いずれか1つ） | 下記「初期選択」のとおり | 選択可 | 「新しい住所を入力する」。送信値は `new` |
| 宛名入力欄 | テキスト入力 | 条件付き必須（サーバー側） | 空 | 入力可 | `maxlength="100"` |
| 郵便番号入力欄 | テキスト入力 | 条件付き必須（サーバー側） | 空（プレースホルダ「1234567」） | 入力可 | `maxlength="7"`・`inputmode="numeric"`。ハイフンなしで入力する |
| 都道府県セレクトボックス | セレクトボックス | 条件付き必須（サーバー側） | 「選択してください」（値は空） | 選択可 | 選択肢は「選択してください」と47都道府県（北海道〜沖縄県、JIS X 0401 の順） |
| 市区町村入力欄 | テキスト入力 | 条件付き必須（サーバー側） | 空 | 入力可 | `maxlength="100"` |
| 町名・番地入力欄 | テキスト入力 | 条件付き必須（サーバー側） | 空 | 入力可 | `maxlength="200"` |
| 建物名入力欄 | テキスト入力 | 任意 | 空 | 入力可 | `maxlength="200"` |
| 電話番号入力欄 | テキスト入力 | 条件付き必須（サーバー側） | 空（プレースホルダ「09012345678」） | 入力可 | `maxlength="11"`・`inputmode="numeric"`。ハイフンなしで入力する |
| 配送先のエラーメッセージ | テキスト（条件表示） | - | 非表示（エラーがある場合のみ各項目の下に表示） | 表示のみ | 2.2 のエラーメッセージを項目ごとに表示 |

- **初期選択**: 既定の住所があればそのラジオボタン、既定の住所が無く登録済み住所があれば先頭の住所、登録済み住所が1件も無ければ新しい住所ラジオボタンを選択済みにする。
- 新しい住所の入力欄は、選択中のラジオボタンにかかわらず常に表示する。入力値は新しい住所ラジオボタンを選択している場合のみ使用し、登録済み住所を選択している場合は入力されていても無視する（エラーにもしない）。

### 1.4 支払方法

| 表示名（論理名） | 種別 | 必須性 | 初期値／表示内容 | 操作可否 | 備考 |
|---|---|---|---|---|---|
| 支払方法ラジオボタン | ラジオボタン | 必須（サーバー側） | 未選択 | 選択可 | 「クレジットカード」（`CREDIT_CARD`）／「銀行振込」（`BANK_TRANSFER`）／「代金引換」（`CASH_ON_DELIVERY`）の3つ |
| 支払方法のエラーメッセージ | テキスト（条件表示） | - | 非表示 | 表示のみ | 「支払方法を選択してください」 |

- 実際の決済処理（カード情報の入力・決済代行サービスとの連携）は行わない。選択した支払方法を注文に記録するのみとする。

### 1.5 操作・その他

| 表示名（論理名） | 種別 | 必須性 | 初期値／表示内容 | 操作可否 | 備考 |
|---|---|---|---|---|---|

| カートに戻るリンク | リンク | - | 「カートに戻る」 | 遷移可 | `GET /cart` へ遷移。入力内容は破棄される |

## 2. 入力チェック内容

### 2.1 クライアント側

- 新しい住所の各入力欄に `maxlength`（1.3 の備考のとおり）を付与する。上限を超える文字数は入力できない。
- 新しい住所の入力欄は「新しい住所を入力する」選択時のみ必須となるため、`required` 属性は付与しない。支払方法のラジオボタンにも `required` を付与しない。必須チェックはすべてサーバー側で行う。
- JavaScriptによる入力チェックは行わない（二重送信防止のボタン無効化のみ行う）。

### 2.2 サーバー側

`POST /checkout` 送信時にチェックする。文字列項目は前後の空白（半角・全角スペース）を除去してからチェックする。

| 対象項目 | チェック内容 | エラーメッセージ | 発生条件 |
|---|---|---|---|
| 配送先の選択 | `new` またはログインユーザーの `addresses.id` であること | 「配送先を選択してください」 | 未選択・他ユーザーや存在しない住所IDを送信するリクエスト改ざん時 |
| 宛名 | 必須 | 「宛名を入力してください」 | 新しい住所を選択し、未入力の場合 |
| 宛名 | 100文字以内 | 「宛名は100文字以内で入力してください」 | 新しい住所を選択した場合。画面操作では `maxlength` により発生しない |
| 郵便番号 | 必須 | 「郵便番号を入力してください」 | 新しい住所を選択し、未入力の場合 |
| 郵便番号 | 半角数字7桁（`^[0-9]{7}$`） | 「郵便番号はハイフンなしの半角数字7桁で入力してください」 | 新しい住所を選択し、7桁未満・数字以外（ハイフン・全角数字を含む）の場合 |
| 都道府県 | 47都道府県のいずれかであること | 「都道府県を選択してください」 | 新しい住所を選択し、未選択の場合。一覧に無い値を送信するリクエスト改ざん時 |
| 市区町村 | 必須 | 「市区町村を入力してください」 | 新しい住所を選択し、未入力の場合 |
| 市区町村 | 100文字以内 | 「市区町村は100文字以内で入力してください」 | 新しい住所を選択した場合。画面操作では `maxlength` により発生しない |
| 町名・番地 | 必須 | 「町名・番地を入力してください」 | 新しい住所を選択し、未入力の場合 |
| 町名・番地 | 200文字以内 | 「町名・番地は200文字以内で入力してください」 | 新しい住所を選択した場合。画面操作では `maxlength` により発生しない |
| 建物名 | 200文字以内 | 「建物名は200文字以内で入力してください」 | 新しい住所を選択した場合。画面操作では `maxlength` により発生しない |
| 電話番号 | 必須 | 「電話番号を入力してください」 | 新しい住所を選択し、未入力の場合 |
| 電話番号 | 半角数字10〜11桁（`^[0-9]{10,11}$`） | 「電話番号はハイフンなしの半角数字10〜11桁で入力してください」 | 新しい住所を選択し、10桁未満・数字以外（ハイフン・全角数字を含む）の場合 |
| 支払方法 | `CREDIT_CARD`／`BANK_TRANSFER`／`CASH_ON_DELIVERY` のいずれかであること | 「支払方法を選択してください」 | 未選択の場合。一覧に無い値を送信するリクエスト改ざん時 |

- 同じ項目で必須と形式・文字数の両方に該当する場合は、必須のエラーメッセージのみ表示する。
- 複数の項目にエラーがある場合は、すべての項目のエラーメッセージを同時に表示する。

## 3. 画面処理

### 3.1 遷移元

- 通常はカート画面の購入手続きへ進むボタンから遷移する。`GET /checkout` はURLを直接指定してもアクセスできるため、表示前に 3.2 の事前チェックを行う。
- ログインが必要。未ログインでアクセスした場合はログイン画面へリダイレクトされ、ログイン後に購入手続き画面へ戻る（「ecsite-画面一覧・共通仕様書.md」の4章）。

### 3.2 初期表示

- `GET /checkout` にアクセスすると、`CheckoutController#show` がログインユーザーの `cart_items`・`products`・`addresses` を取得し、購入手続き画面を表示する。
- **事前チェック**: 以下に該当する場合は画面を表示せず、`/cart` へリダイレクトしてフラッシュメッセージ（エラー）を表示する。
  - カートが0件: 「カートに商品が入っていません」
  - カートに購入不可の商品（非公開・在庫切れ・在庫不足。「ecsite-カート画面設計書.md」の1.1 の条件）がある: 「購入できない商品がカートに含まれています。数量を変更するか削除してください」

### 3.3 注文確定（正常時／バリデーションエラー時／確定できない場合）

- 配送先・支払方法を選択して注文を確定するボタンを押下すると、`POST /checkout`（リクエストパラメータ `addressId`、新しい住所の各項目、`paymentMethod`）が送信される。
- **バリデーションエラー時**: 注文は作成せず、リダイレクトせずに購入手続き画面をそのまま再表示する。配送先の選択、新しい住所の入力値、支払方法の選択は保持し、エラーのある項目の下にエラーメッセージを表示する。注文内容・金額は再表示時点のカートと価格で再計算する。
- **正常時**: バリデーション通過後、`OrderService#placeOrder` が以下を1トランザクションで行う（「ecsite-ER図・テーブル定義書.md」の5章）。
  0. カート・商品を取得し、3.2 と同じ事前チェックを行う。該当する場合はトランザクションをロールバックし、注文を作成せず `/cart` へリダイレクトして同じメッセージを表示する（画面表示後に別タブでカートを変更した場合、在庫が減った場合など）
  1. 新しい住所を選択した場合は `addresses` に保存する。ログインユーザーに既定の住所が無ければ `is_default = true`、あれば `false` とする
  2. カート内の各商品の `products.stock_quantity` から数量を減算する（`version` による楽観ロック）
  3. `orders` を作成する。金額（商品合計・送料・支払総額）は**確定時点**の `products.price` で計算し、配送先は選択した住所の値をコピーする。`status` は `ORDERED`、`ordered_at` は現在日時とする
  4. カートの各明細について `order_items` を作成する（商品名・単価を `products` からコピー）
  5. ログインユーザーの `cart_items` を全件削除する

  完了後、`/orders/{注文番号}/complete` へリダイレクトする（画面としては「ecsite-注文完了画面設計書.md」を参照）。
- **注文番号**: `yyyyMMdd-` + 6桁の乱数（例: `20260921-483920`）とする。`yyyyMMdd` は注文日。既存の注文番号と重複した場合は乱数を取り直し、3回重複した場合はシステムエラー（500）とする。
- **他の購入と競合した場合**: 在庫減算時に楽観ロックの競合（`ObjectOptimisticLockingFailureException`）が発生した場合は、トランザクション全体をロールバックし（新しい住所も保存されない）、`/cart` へリダイレクトしてフラッシュメッセージ（エラー）「他のお客様の購入と重なったため注文を確定できませんでした。カートの内容を確認して、もう一度お試しください」を表示する。
- 画面表示後に商品の価格が変更されていた場合、注文は確定時点の価格で作成される（画面に表示していた金額と異なっても警告は表示しない）。
- 二重送信: ボタンの無効化をすり抜けて2回目の `POST /checkout` が届いた場合、1回目でカートが空になっているため事前チェックにより `/cart` へリダイレクトされ、注文は1件だけ作成される。

### 3.4 カート画面への遷移

- カートに戻るリンク押下により `GET /cart` へ遷移する。入力内容は送信されず、注文・住所は作成されない。

### 3.5 例外発生時の共通事項

- DBアクセス例外等が発生した場合は、「ecsite-画面一覧・共通仕様書.md」の6章のとおり500エラーページを表示する。注文確定処理はロールバックされ、在庫・注文・住所・カートは処理前の状態のままとなる。
