# ecsite 会員登録画面設計書

画面名: 会員登録画面（SC-06）。対応パス: `GET /signup`（表示）／`POST /signup`（登録）。テンプレート: `templates/auth/signup.html`。対応コントローラ: `SignupController`（`app/src/main/java/com/example/ecsite/controller/SignupController.java`）。登録処理は `UserService`（`app/src/main/java/com/example/ecsite/service/UserService.java`）で行う。本書は `doc/詳細設計/ecsite-ER図・テーブル定義書.md` および `doc/詳細設計/ecsite-画面一覧・共通仕様書.md` を根拠に作成した会員登録画面単体の詳細設計書であり、実装前の新規設計である。ログイン画面については「ecsite-ログイン画面設計書.md」を参照。

## 2. 入力チェック内容

### 2.1 クライアント側

- 氏名・メールアドレス・パスワード・パスワード（確認）に `required` を付与する。未入力の場合はブラウザ標準の制約検証により送信されない。
- メールアドレス入力欄は `type="email"` のため、`@` を含まない等メールアドレスの形式でない値はブラウザ標準の制約検証により送信されない。
- パスワード・パスワード（確認）に `minlength="8"` を付与する。1〜7文字の場合は送信されない。
- 各入力欄に `maxlength`（1章の備考のとおり）を付与する。上限を超える文字数は入力できない。
- パスワードの文字種・一致、電話番号の形式はクライアント側ではチェックしない。JavaScriptによる入力チェックは行わない。

### 2.2 サーバー側

`POST /signup` 送信時にチェックする。氏名・メールアドレス・電話番号は前後の空白（半角・全角スペース）を除去してからチェックし、メールアドレスは小文字に変換する。パスワードは空白を除去しない。

| 対象項目 | チェック内容 | エラーメッセージ | 発生条件 |
|---|---|---|---|
| 氏名 | 必須 | 「氏名を入力してください」 | 空白のみを入力した場合。未入力は `required` により通常発生しない |
| 氏名 | 100文字以内 | 「氏名は100文字以内で入力してください」 | 画面操作では `maxlength` により発生しない |
| メールアドレス | 必須 | 「メールアドレスを入力してください」 | 空白のみを入力した場合。未入力は `required` により通常発生しない |
| メールアドレス | 255文字以内 | 「メールアドレスは255文字以内で入力してください」 | 画面操作では `maxlength` により発生しない |
| メールアドレス | 形式（`^[^@\s]+@[^@\s]+\.[^@\s]+$`） | 「メールアドレスの形式が正しくありません」 | ドメイン部に `.` が無い値（例: `user@localhost`）など、ブラウザの `type="email"` 検証を通過するが形式に合わない場合 |
| メールアドレス | 未登録であること（小文字変換後の値で `users.email` と照合） | 「このメールアドレスは既に登録されています」 | 登録済みのメールアドレス（大文字・小文字の違いのみのものを含む）を入力した場合 |
| パスワード | 必須 | 「パスワードを入力してください」 | 未入力は `required` により通常発生しない |
| パスワード | 8〜64文字 | 「パスワードは8〜64文字で入力してください」 | 画面操作では `minlength`・`maxlength` により発生しない |
| パスワード | 半角英数字・記号（`!`〜`~`、空白を含まない）のみ | 「パスワードに使用できるのは半角英数字と記号のみです」 | 全角文字・空白を含む場合 |
| パスワード | 半角英字と数字をそれぞれ1文字以上含む | 「パスワードは英字と数字をそれぞれ1文字以上含めてください」 | 英字のみ・数字のみ・記号と一方のみの場合 |
| パスワード（確認） | 必須 | 「パスワード（確認）を入力してください」 | 未入力は `required` により通常発生しない |
| パスワード（確認） | パスワードと一致すること | 「パスワードが一致しません」 | パスワードとパスワード（確認）が異なる場合 |
| 電話番号 | 入力された場合、半角数字10〜11桁（`^[0-9]{10,11}$`） | 「電話番号はハイフンなしの半角数字10〜11桁で入力してください」 | ハイフン・全角数字を含む、10桁未満の場合 |

- 1つの項目で複数のチェックに該当する場合は、表の上の行（必須 → 文字数 → 形式・文字種 → 組み合わせ → 重複・一致）を優先し、最初に該当したエラーメッセージのみ表示する。
- 複数の項目にエラーがある場合は、すべての項目のエラーメッセージを同時に表示する。
- パスワード（確認）の一致チェックは、パスワード自体にエラーが無い場合のみ行う。

## 3. 画面処理

### 3.1 遷移元

- 共通ヘッダーの会員登録リンク、ログイン画面の会員登録リンクから遷移する。
- **ログイン中にアクセスした場合**: `GET /signup` は画面を表示せず `/products` へリダイレクトする（「ecsite-画面一覧・共通仕様書.md」の4章）。

### 3.2 初期表示

- `GET /signup` にアクセスすると、`SignupController#form` が空の入力フォームを表示する。

### 3.3 登録（正常時／バリデーションエラー時）

- 各項目を入力して登録するボタンを押下すると、`POST /signup` が送信される。
- **正常時**: `UserService#register` が `users` を作成する（メールアドレスは小文字に変換した値、パスワードは BCrypt でハッシュ化した値、電話番号は未入力なら NULL）。作成後、登録したユーザーでログインした状態にし（セッションに認証情報を保存）、`/products` へリダイレクトしてフラッシュメッセージ（成功）「会員登録が完了しました」を表示する。共通ヘッダーはログイン中の表示になる。
- **バリデーションエラー時**: ユーザーは作成せず、リダイレクトせずに会員登録画面をそのまま再表示する。氏名・メールアドレス・電話番号の入力値は保持し、パスワード・パスワード（確認）は空にする。エラーのある項目の下にエラーメッセージを表示する。
- **同時登録による重複**: 重複チェック通過後、保存時に他のリクエストが同じメールアドレスを先に登録していた場合（一意制約 `uq_users_email` 違反）も、バリデーションエラー時と同様に「このメールアドレスは既に登録されています」を表示して再表示する。

### 3.4 ログイン画面への遷移

- ログイン画面へのリンク押下により `GET /login` へ遷移する。入力内容は破棄される。

### 3.5 例外発生時の共通事項

- DBアクセス例外等が発生した場合は、「ecsite-画面一覧・共通仕様書.md」の6章のとおり500エラーページを表示する。ユーザーは作成されない。
