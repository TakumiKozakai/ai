name: create-unit-testcase-server-error
description: 設計書（自由形式のMarkdown）を読み込み、画面単位の試験項目票のうちサーバ処理内のエラー（DBエラー、ファイル操作エラー、AWSサービスアクセスエラー等）を起票する。「サーバエラー系の試験項目を作って」等の依頼、または create-unit-testcase-for-screen から呼び出されて使用する。
---

引数 `$ARGUMENTS` で渡された「設計書ファイルパス」（および省略可能な「出力先ディレクトリ」）をもとに、以下の手順でサーバエラー系の試験項目票を作成してください。

1. `$ARGUMENTS` から設計書ファイルパスと出力先ディレクトリを読み取る
   - 出力先ディレクトリが省略された場合は、設計書ファイルと同じディレクトリを出力先とする
2. 設計書ファイルを読み込み、対象画面の処理が依存する外部リソース（DB、ファイルストレージ、AWSサービス等）とその利用箇所を把握する
   - 設計書に記載がなく判断できない項目は、憶測で補わずユーザーに確認する
3. `.claude/skills/create-unit-testcase-for-screen/references/試験項目票_{画面名称}.md`（`claude-skills/` を基準に解決する）をテンプレートとして読み込む
4. サーバ処理内のエラー系の試験項目を洗い出す
   - 対象: DBエラー（接続断・制約違反・タイムアウト等）、ファイル操作エラー（読み書き失敗・権限エラー等）、AWSサービスアクセスエラー（S3・SQS等への接続失敗・権限エラー等）、その他外部リソース起因の異常
   - 入力値のバリデーション観点（フロント/サーバ）はここでは扱わない（他skillの担当）
5. 各項目について No.・シナリオ・正常/異常・前提条件・操作手順・期待結果を表の1行として記述する
   - 正常/異常列には常に「異常」を記載する
   - 操作手順・期待結果内で複数行になる場合は `<br>` で改行する
   - 前提条件には、エラーを発生させるための外部リソースの状態（例:「DB接続を切断した状態」「S3バケットへのアクセス権限が無い状態」）を具体的に記述する
   - 操作手順の最後に、次の項目に影響を残さないよう外部リソースを正常な状態へ復旧させる手順（例:「DB接続を復旧する」）を含める
   - 期待結果には、画面に表示されるエラーメッセージ・システムの挙動を具体的に記述する
6. No（試験順）は、このファイル内で1から始まる連番（ゼロ埋め不要）とし、実行可能な順序になるよう並べる（ファイルをまたいだ通し番号にはしない）
   - 外部リソースを意図的に異常状態にする項目は、他の項目に影響しないよう最後にまとめて配置し、各項目内で復旧まで完結させることで前後の項目に依存させない
7. DB検証が必要な項目について、表の下の「DB確認用クエリ」セクションに対応No.と確認用クエリ（SQL文）を記載する
8. 該当する試験項目が1件もない場合も、テンプレートのサンプル行（試験項目表のNo.1行、DB確認用クエリ表の`SELECT ...`行）を削除し、見出し行と区切り行のみを残したファイルを作成し、「該当する試験項目なし」の旨を本文に記載する
9. 出力先ディレクトリに `試験項目票_{画面名称}_03_異常系.md` として保存する
   - 既に同名ファイルが存在する場合は上書きしてよいか確認する
10. 作成した試験項目の件数（0件の場合はその旨）と保存先ファイルパスを報告する
