name: review-unit-testcase-for-screen-from-source
description: 対象画面のソースコード（テンプレート・コントローラ等）をもとに、画面単位の試験分類別試験項目票（正常系・フロントバリデーション・サーババリデーション・サーバエラー）を一括でレビューし、指摘をHTMLに集約する。内部で4つの分類別レビューskillを順に呼び出すオーケストレーターskill。「ソースをもとに試験項目票をレビューして」「実装と分類別の試験票を突き合わせて」等の依頼で使用する。設計書ではなくソースコードと突き合わせる点、対象が画面単位である点が特徴。
---

引数 `$ARGUMENTS` で渡された「対象画面のソースファイルパス（テンプレート・コントローラ等。複数可）」と「試験項目票ディレクトリ」をもとに、以下の手順で試験分類別の試験項目票一式をレビューしてください。

1. `$ARGUMENTS` からソースファイルパス（複数可）と試験項目票ディレクトリを読み取る
   - ソースファイルパスが省略されている場合は、独断で進めずユーザーに確認する。相対パスの場合はカレントディレクトリ基準で解釈する
   - 試験項目票ディレクトリが省略されている場合は、独断で推測せずユーザーに確認する
2. 渡されたソースファイルと、そこから参照される関連ソース（テンプレート・コントローラ・フォームクラス・バリデーション定義・メッセージ定義・サービス・リポジトリ等）を読み込み、対象画面名称を特定する。試験項目票ディレクトリ内の `試験項目票_{画面名称}_*.md` と照合し、一致するファイルが1つも無い、または複数画面分の候補があり一意に特定できない場合はユーザーに確認する
   - 参照すべき関連ソースが特定できない場合は、憶測で補わずユーザーに確認する。画面名称が特定できていれば、一部の関連ソース（例外ハンドラ等）が未解決のままでもレビューは中止せず続行し、未解決事項と確認済みの回答を子skillへ引き継ぐ（子skillは未解決の関連ソースに依存する観点を「未確認」として扱う）
3. 以下4つのskillのSKILL.mdを順に読み込み、その手順に従って実行し、各分類の指摘事項・実行状態（成功／未実施／失敗）・未確認観点を収集する（`.claude/skills/` は本skill自身が配置されている `claude-skills/` を基準に解決する）
   - 呼び出し時には「集約実行であること」「ソースファイルパス（関連ソースを含む）」「試験項目票ディレクトリ」「画面名称」「関連ソースに関する未解決事項・確認済みの回答」を明示して渡す（子skillは集約実行の明示が無い場合、単体実行として振る舞う）
   1. `.claude/skills/review-unit-testcase-normal-case-from-source/SKILL.md`（正常系）
   2. `.claude/skills/review-unit-testcase-front-validation-from-source/SKILL.md`（フロントバリデーション）
   3. `.claude/skills/review-unit-testcase-server-validation-from-source/SKILL.md`（サーババリデーション）
   4. `.claude/skills/review-unit-testcase-server-error-from-source/SKILL.md`（サーバエラー）
   - 各skill実行中にユーザーへの確認（関連ソースの特定等）が発生した場合はそのまま対話し、完了後に次のskillへ進む
   - 担当ファイルが存在しない分類は「未実施」、処理が異常終了した分類は「失敗」として記録し、後続のskillの実行は継続する（1つの分類の失敗で全体を止めない）
   - ユーザーが対話中に全体の中止を明示的に指示した場合は、その時点で後続のskillの呼び出しを中止する
4. 全分類の指摘事項・実行状態・未確認観点を集約する。指摘件数の集計には、未実施・失敗の分類の件数を含めない（実行状態として別途扱う）
   - 指摘が1件以上ある場合は、未実施・失敗の分類の有無にかかわらず5へ進む
   - 指摘が0件の場合はファイルを作成せず6へ進む。未実施・失敗の分類または未確認観点がある場合は「レビュー未完了」の旨を明記して報告する
5. 試験項目票ディレクトリに `試験項目票レビュー結果_{画面名称}_ソース_{実行日時yyyyMMddHHmm}.html` を新規作成し、分類｜種別｜対象No.｜指摘内容｜根拠の5列表として出力する（既存の試験結果票・試験項目票レビュー結果HTMLと同様のスタイルとし、見出し・対象画面・照合元（ソースファイルパス）・実行日時・分類別の集計表・指摘表で構成する）。全4分類それぞれの実行状態（成功／未実施／失敗）と未確認観点を明記し、失敗した分類はその失敗理由もあわせて記載する
   - 指摘内容・根拠に含まれるテンプレート断片・コード・文言等はHTMLエスケープし、秘密情報はマスクする
   - 既に同名ファイルが存在する場合は上書きせず、末尾に `_2`, `_3` … を付与した名前で保存する
6. 最後に、分類ごとの指摘件数・実行状態（失敗の場合は失敗理由。秘密情報はマスクする）・未確認観点と、HTMLを作成した場合はその保存先パスを報告する
7. 試験項目票ファイル・ソースコードは変更しない

## スコープ外

- 指摘の試験項目票への自動反映は行わない（レビューのみ）
- `finalize-unit-testcase-for-screen` との連携は行わない
- 設計書との突き合わせは行わない（`review-unit-testcase-for-screen` の担当）
- 単一ファイル形式の試験項目票（`試験項目票_{画面名称}.md`）のレビューは行わない（`review-unit-testcase` の担当）
- API・バッチ用の試験項目票はレビューしない
