引数 `$ARGUMENTS` で渡された「設計書ファイルパス」「比較基準となるコミットID」をもとに、以下の手順で実装のレビューを行ってください。

1. `$ARGUMENTS` から設計書ファイルパスとコミットIDを読み取る
   - いずれか省略されている場合は、独断で進めずユーザーに確認する。コミットIDを自動で提案することはしない
   - 設計書パスが相対パスの場合はカレントディレクトリ基準で解釈する
2. 実装先プロジェクト（ルートディレクトリ。設計書の保存場所と必ずしも一致しない）をユーザーに確認する
3. 実装先プロジェクトが属するリポジトリのHEAD時点と指定コミットID時点の間のコード変更差分を `git diff` で取得する（未コミットの変更は対象外）
   - コミットIDが不正で解決できない場合はユーザーに確認する
   - 差分が無い場合は、その旨を報告して終了する（レビューは実施しない）
4. 設計書が属するリポジトリのHEAD時点の設計書ファイルの内容を、一致確認・文脈理解のために参照する（未コミットの変更は含めない）
   - HEAD時点で設計書ファイルが存在しない・リネームされている場合や、設計書がGit管理外の場合はユーザーに確認する
5. 以下4つのskillのSKILL.mdを順に読み込み、その手順に従って同じ設計書ファイルパス・コミットID・実装先プロジェクトのルートディレクトリを渡して実行し、各観点の指摘事項と実行状態（成功/失敗）を収集する（`.claude/skills/` は claude-skills/ を基準に解決する）
   1. `.claude/skills/review-implementation-against-design-doc/SKILL.md`
   2. `.claude/skills/review-implementation-for-bugs/SKILL.md`
   3. `.claude/skills/review-implementation-for-performance/SKILL.md`
   4. `.claude/skills/review-implementation-for-security/SKILL.md`
   - あるskillの処理が異常終了した場合は、その観点を「レビュー未完了」として記録し、後続のskillの実行は継続する
6. 全skillの指摘事項・実行状態を集約する。指摘件数の集計には未完了観点の件数を含めない（未完了観点は指摘0件として数えず、実行状態として別途扱う）
   - 指摘が1件以上ある場合は、未完了の観点の有無にかかわらず7へ進む
   - 指摘が0件で、未完了の観点が1つ以上ある場合はファイルを作成せず、チャットで「レビュー未完了」の旨と観点別の失敗理由（秘密情報が含まれる場合はマスクする）を報告し、7はスキップして8へ進む
   - 指摘が0件で、全観点が完了している場合はファイルを作成せず、確認した観点とともにその旨をチャットで報告し、7はスキップして8へ進む
7. 実装先プロジェクトのリポジトリ直下に `レビュー結果_実装_{対象}_{実行日時yyyyMMddHHmm}.html` を新規作成し、種別（観点）｜指摘内容｜根拠の3列表として出力する（既存の試験結果票と同様のスタイルのHTMLとする）。全4観点それぞれの実行状態（成功/未完了）を明記し、未完了の観点があればその失敗理由もあわせて記載する。コード等の引用はHTMLエスケープし、指摘・根拠・失敗理由に含まれる秘密情報はマスクする
   - `{対象}` には設計書ファイル名（拡張子を除いたもの）を用いる
   - 既に同名ファイルが存在する場合は上書きしてよいか確認する
8. 最後に、観点別の指摘件数・実行状態（成功/未完了、未完了の場合は失敗理由。秘密情報が含まれる場合はマスクする）と、HTMLを作成した場合はその保存先パスを報告する

## スコープ外

- 設計書自体の作成・更新は行わない
- 実装（implement-from-design-doc / implement-from-design-doc-diff）との統合は行わない
- 試験項目票レビュー（review-unit-case-* 等）との統合は行わない
- 検出した指摘の自動修正は行わない（レビューのみ）
